# Support playbook

CommitGuard support is local-first. Most requests can be answered without
sending source code, reports, or credentials to a third party. This playbook
defines what to collect, how to triage, and when to escalate.

## Before opening a request

1. Run `commit-guard --version` and `commit-guard doctor` in the affected
   repository.
2. Reproduce with the smallest scope: `commit-guard scan --staged`,
   `commit-guard gate --report <local-report>`, or the exact failing command.
3. Confirm whether the problem reproduces with bundled rules and without user
   configuration:
   ```bash
   commit-guard scan --no-cache --no-baseline --staged
   ```
4. Check [TROUBLESHOOTING.md](TROUBLESHOOTING.md) for hooks, paths, caches,
   formats, and false-positive guidance.

## What to include

Include the following, redacted where necessary:

- CommitGuard version, operating system, Python version, install method
  (`pipx`, wheel, zipapp, container, Homebrew, Scoop, or source).
- The exact command and exit code.
- A minimal report or a synthetic reproduction. Do not send secrets; replace
  them with stable placeholders.
- Relevant policy, triage, or baseline snippets with owner names and ticket
  identifiers removed.
- For plugin issues: `plugin.json`, the entrypoint digest, and the output of
  `commit-guard plugin verify --dir <dir>`.
- For ingestion issues: the producer name and version, the report format, and
  a reduced sample that preserves the failing shape.
- For performance issues: fixture size, `commit-guard --version`, and the JSON
  output from `benchmarks/scan_benchmark.py`.

Never send live tokens, private keys, customer source, or unredacted secret
findings. CommitGuard masks secret values in generated reports, but local
artifacts can still contain sensitive context.

## Triage matrix

| Class | Examples | First response | Target resolution |
|---|---|---|---|
| P1 Security | Secret exposure, unsigned artifact accepted, plugin escape, ingestion path traversal | Acknowledge and contain | 2 business days |
| P1 Release blocker | Crash on documented install path, gate bypass, false clean result | Acknowledge and reproduce | 3 business days |
| P2 Functional | Parser rejects a valid report, IDE/LSP failure, merge or audit failure | Classify and request artifacts | 10 business days |
| P3 Accuracy | Missing detection or noisy rule with a reduced reproduction | Add to accuracy corpus | Next release |
| P4 Documentation | Unclear setup, help text, packaging instructions | Document fix | Next documentation pass |

Security reports follow [SECURITY.md](../SECURITY.md), not the public issue
tracker.

## Local evidence bundle

A support bundle should be generated by the operator, not uploaded
automatically. A minimal bundle is:

```bash
commit-guard --version > support/version.txt
commit-guard doctor . > support/doctor.txt 2>&1
commit-guard audit . --reports commit_guard_reports \
  --since 2026-01-01 --until 2026-03-31 \
  --format json --output support/audit.json
commit-guard plugin verify --dir plugins > support/plugins.txt 2>&1
```

Review every file before sharing it. Reports can contain file paths, rule
metadata, and redacted snippets.

## Reproducing with a reference monorepo

For multi-tool issues, collect one report per tool and one CommitGuard report,
then merge them without scanning:

```bash
commit-guard report merge artifacts/ \
  --repo . --output support/merged.json
commit-guard gate --report support/merged.json --profile audit --format json
commit-guard audit . --reports artifacts/ --format json
```

This reproduces normalization and gate behavior from local artifacts and is
the preferred format for cross-tool support cases.

## Escalation

Escalate when any of the following is true:

- A finding marked clean is later shown to be exploitable.
- A signed artifact fails verification or an unsigned artifact is accepted.
- A plugin reads or writes outside its documented directory or requests
  network access in protocol v1.
- A report can escape the repository path without `--allow-outside`.
- A regression affects the fixed-commit accuracy corpus or benchmark gate.

Commercial support is available separately. It does not change the local-first
data model: support works from operator-provided evidence bundles and does not
require hosted telemetry.
